# Subject vocabulary for the built-in (CLIP) tagger.
#
# One label per line, optionally followed by `> parent`. A photo tagged with a
# label also gets that label's parents (golden retriever -> dog -> animal), so
# the filter rail can offer both "golden retriever" and "dog". Every parent must
# itself be a label somewhere in this file; order does not matter.
#
# A name in [brackets] is a *group*: it organises the hierarchy (and pools its
# children's scores) but is never scored on its own or written as a tag. Use it
# for roots too generic to be worth filtering by ("object"), or that would
# collide with a genre of the same name ("landscape", "event").
#
# Rules, all enforced by tests in `tagger/builtin.rs`:
# - lowercase, singular, spaces not underscores, at most 40 characters
# - no duplicates, no cycles
#
# Pick things a camera actually sees and a person would actually filter by.
# Each label costs one text embedding (cached on disk) and a dot product per
# photo, so a few thousand is fine — but every near-synonym splits the model's
# vote, so prefer one clear word per concept.
