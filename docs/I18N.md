# Languages in the interface

The interface ships in English, German, Spanish, French and Japanese. This is
how its words are kept, and the rules for adding one.

## Where the words live

- `src/i18n/index.ts` — `t`, `tx`, the number/date/list formatters, and the
  language switch.
- `src/i18n/en/<area>.ts` — **the source.** Every string the interface shows,
  one file per area of the app. Its keys are the type every call and every
  other language is checked against.
- `src/i18n/{de,es,fr,ja}/<area>.ts` — the translations, mirroring `en/`.
  Partial: a key a language does not have yet shows in English.
- `src/i18n/pseudo.ts` — the development-only pseudo-locale (Settings › About ›
  Language › Pseudo). Every string accented and padded: anything still plain
  English on screen is hard-coded, and a clipped `]` is a layout that will not
  fit a longer language.

| Area       | Covers |
|------------|--------|
| `common`   | Words used everywhere: OK, Cancel, Close, … Use only when the meaning is exactly the same. |
| `shell`    | App frame: mode rail, top bar, command palette, shortcuts, tour, dialogs, menus, error screens. |
| `library`  | Browse: grid, context header, photo menu, selection panel, collections, library menu. |
| `filters`  | Filter rail, date picker, the search reading, suggestions, survey. |
| `cull`     | Cull and Compare. |
| `develop`  | Develop's frame, panels and looks. |
| `tools`    | Develop's tools: masks, spot, crop, curve, wheels, sliders, AI denoise. |
| `people`   | People and faces. |
| `places`   | Places, the map, GPX. |
| `transfer` | Import, export, the export queue. |
| `settings` | Settings tabs, AI setup, backups, diagnostics, Activity. |
| `store`    | Messages raised from the store (`store.ts`, `store/`) and `lib/api.ts`. |
| `viewer`   | Lightbox and the zoomable image. |
| `core`     | Words for text the Rust core sends: its error messages, progress, AI status, model purposes (`lib/coreText.ts`). |
| `content`  | Named things the core defines: looks, presets, default mask names, lighting conditions (`lib/content.ts`). |

## What the core sends

The core words its errors and progress in English, and the frontend translates
them on the way in rather than the core learning languages:

- **Errors** are translated where every command error passes, in `lib/api.ts`
  (`translateCoreError`), in two ways:
  - **Authored messages** ("a place needs a name") are matched by a
    table of the core's own wording, parameters and all.
    `lib/coreText.test.ts` reads the Rust sources and fails if a message the
    table knows is reworded there, so a changed message is caught rather than
    silently left English.
  - **System failures** — the OS, SQLite, LibRaw, the network — have no fixed
    wording, so the core classifies them instead (`src-tauri/src/errors.rs`):
    `err()` walks the cause chain, names the root cause's kind (`notFound`,
    `accessDenied`, `fileInUse`, `diskFull`, `catalogueBusy`, `offline`, …)
    and sends it as JSON with the file it concerned and the English chain.
    The interface words the kind (`core.sys.*`), after the core's own
    sentence for what it was doing when the table knows it. Errors thrown
    from `api.ts` are `CoreError`s carrying the English, which is what the
    error log writes. A cancel is never classified: it stays the plain word
    `isCancelled` looks for.
- **Progress** is worded from the event's `phase` and message (`progressText`).
- **Named content** — looks, styles, lighting conditions — is keyed on the
  core's stable id or English name (`lib/content.ts`), with the same kind of
  guard test. A LUT the user imported, or a mask they named, is their own
  words and is never translated. Default mask names are translated when shown,
  never when saved, so a saved edit stays the same in every language.
- **Countries** come from `Intl.DisplayNames`: the core sends English country
  names, `lib/countryCodes.ts` (generated by `scripts/gen-countries.mjs` from
  the core's `countries.tsv`) maps them to ISO codes. Town names are GeoNames'
  own and stay as they are.
- **Tags** are stored, filtered on and written into files (XMP keywords) in
  English, whatever the language: they are the catalogue's keys, and genre
  drives the cull rubric. They are *named* for display (`tagName`):
  - the built-in tagger's ~1,630 words and the genres by the fixed tables in
    `src/i18n/tags/<lang>.ts`;
  - the tags a vision model wrote freely by the model itself: `lib/tagNames`
    asks the core's `translate_tags` for the ones no table covers, the local
    model names them (text only, schema-constrained, each answer paired with
    its English so none lands on the wrong tag), and the catalogue keeps them
    (`tag_translations`). It asks once per language and after every tagging
    or describing pass, when the model is loaded. With no model running, a
    tag reads in English until one is.
- **Descriptions** (Detailed descriptions) are prose, so they are written in
  the interface's language: `start_tagging` and `start_captioning` take the
  language, and the prompt asks for the description in it while keeping the
  tags English. A description is written once; one made before a change of
  language stays in the language it was written in.

## The search box

`lib/queryReading.ts` reads people, places, dates, gear and genres out of a
search. It reads English, and in another language it also reads that
language's words through `src/i18n/query/<lang>.ts`, a list of local words and
the English word each stands for ("letzten" → last, "été" → summer). Month
names come from `Intl`; French and Spanish put "last" after the noun
(`postfix`); Japanese is split with `Intl.Segmenter` and reads a few phrases
whole (去年の夏 is the summer of last year). What was typed is what the chips
show. Whatever is left is content search, and SigLIP 2 reads that in any
language, so it needs no translating.

## The rules

1. **Every string a person reads goes through `t`.** Text in JSX, `title`,
   `aria-label`, `placeholder`, `alt`, toasts, confirm and prompt dialogs,
   labels in tables. Not: console output, error-log text, ids, CSS classes,
   event names, `data-*` hooks, product and OS names (SourceLight, Finder), and
   the legal documents (the licence and the third-party notices are shown as
   written: a translation of a licence is not the licence).
2. **Keys are `area.place.what`**, camelCase segments:
   `library.photoMenu.moveToTrash`. The key names where it is and what it is,
   never the English wording.
3. **Whole sentences, never fragments.** `"Imported " + n + " photos"` cannot
   be translated — the word order differs. One key per complete sentence, with
   placeholders: `"Imported {count} photos"`. A sentence that changes with a
   condition is two keys, not a sentence with a swapped-in piece.
4. **Plurals are objects**, never `n === 1 ? "" : "s"`:
   `{ one: "{count} photo", other: "{count} photos" }`, called with `count`.
   `other` is required. The form is chosen by `Intl.PluralRules`, so German gets
   two forms, Japanese one, and Polish could have four.
5. **Numbers go in as numbers** and are formatted for the language (1,234 ·
   1.234). Drop `.toLocaleString()`. Years, ids and values already formatted go
   in as strings. Dates use `formatDate` from `i18n`, not `toLocaleString`.
6. **Markup inside a sentence uses `tx`**: `tx("library.selected", { count:
   <span className="tabular-nums">{n}</span> }, n)` keeps the span where the
   language puts the number. The third argument picks the plural form.
7. **Never call `t` at module scope.** A table built at import time is built in
   whatever language was active then, and does not change when the user
   switches. Put keys in the table (`label: "settings.tab.ai"`, typed `Key`)
   and call `t(item.label)` where it renders, or make the table a function.
   The same goes for `useMemo`/`useState` initialisers that would hold a
   translated string across a change of language.
8. **Context for the translator** goes in a comment above the key when the
   English is ambiguous: is "Pick" a verb or the cull verdict? Is "Export" a
   button or a heading?
9. **Strings from the Rust core are shown as they come** (error details, look
   names, default mask names). They stay English for now — see below.

## Switching language

The choice is `language` in the store (persisted; `"system"` by default),
resolved against `navigator.languages` with a fallback to English. The
catalogue is loaded before the first render, so the window never flashes
English. A change re-renders the tree from `LocaleRoot` in `main.tsx`; nothing
in the tree is memoised, so every `t` runs again. The Mac menu bar rebuilds on
a change.

## Checks

`src/i18n/catalogues.test.ts` fails when an English key appears in two areas or
outside its area's prefix, a translation has a key English does not, a
translation drops or renames a placeholder, or a plural lacks `other`.

`npm run i18n:missing` lists what each language has not translated yet — a
count per area, or with a language code (`npm run i18n:missing -- de`) every
missing key beside its English. A new English string does not have to be
translated in the same change; it shows in English until it is.

Each language folder has a `GLOSSARY.md`: the words chosen for the app's
recurring terms (Cull, Develop, Pick, Look…). Keep new strings to it, and
give it to whoever reviews the translation.

## Not yet translated

- **Unclassified core errors**: a failure whose root cause `errors.rs` does
  not recognise (GPU errors, which reach it as text), and an authored message
  the table has not learned yet. These show in English.
- **Undo history.** A step's label is worded when the edit is made and saved
  with the edit, so a history started in one language keeps those words after
  a switch.
- **Free-text tags until a model has named them** — a vision model's, or ones
  the user typed (these go to the model like any other; one already in the
  user's language comes back unchanged and stays as typed).
- **Descriptions written before a change of language.**
- **SourceLight's licence and the third-party licences**: legal text, English
  by design.
- **Native surfaces**: installer (NSIS), the Windows jump list, the macOS
  AppKit Edit menu (localised by macOS itself once the bundle declares
  `CFBundleLocalizations`).
